# Как работает агент (`agent.py`)

Портфель экспертов (история + LLM) предлагает гипотезы → адаптивные пилоты → совместный апостериор → MILP-план под лимиты. pandas/numpy/scipy + stdlib. Без LLM-ключа (`OPENROUTER_API_KEY` / `OPENAI_API_KEY`) детерминирован. Настройки — [configuration.md](configuration.md), замеры и отброшенные идеи — [experiments.md](experiments.md).

## Ключевое наблюдение
Эффект кампании зависит только от **ячейки** `(current_tariff, arpu_segment)`, целевого тарифа и канала. Канал лишь умножает эффект (`ratio = pct × conv × mult`). Отсюда:
- гипотеза — это `ячейка × target`: всего 63 ячейки, фильтры data/call на эффект не влияют;
- один пилот через SMS даёт оценку сразу для всех каналов: `base = observed / 0.65`;
- стоимость контакта мала по сравнению с приростом, поэтому результат ограничивают охват и бюджет, а не окупаемость.

## Алгоритм
1. **Prior.** Из `data/change_tariff.csv` для каждой тройки (from, seg, to) считаем `base = средний Δ% ARPU × доля переходов`. Среднее сжимается к 0 при малом числе наблюдений. Ширина prior растёт с долей перехода: `σ = √(0.03² + (1.0·доля)²)` (`PRIOR_SD="share"`). Эффект = Δ% × конверсия, поэтому крупный эффект возможен только у частого перехода; плоская ширина 0.25 тратила пилоты на редкие переходы с заведомо малым эффектом.
2. **Рукава — портфель экспертов.** Эксперты предлагают рукава `(ячейка, target)` в общий реестр. У каждого рукава гауссов апостериор (μ, σ²) и `src` — кто его предложил.
   - **prior:** 4 target с наибольшим потенциалом μ + σ. Сначала переходы, которые в истории были, пары без истории — только на свободные места: иначе пара с μ = 0 обгоняет переход с μ < 0, съедает пилоты и в план не попадает.
   - **llm:** один вызов OpenAI-совместимого API (stdlib `urllib`, timeout 60 с): есть `OPENROUTER_API_KEY` → OpenRouter, модель из `LLM_MODEL` или селектора в Cockpit; иначе OpenAI по `OPENAI_API_KEY`/`OPENAI_MODEL`. Получает таблицы тарифов и ячеек, возвращает до 2 target на ячейку с оценкой эффекта. Невалидные тарифы и ячейки отбрасываются, оценка клипуется в ±0.5. Сбой или нет ключа → эксперт молча выключается.
   - Если рукав предложили оба, μ берётся из истории.
   - Мета-выбор между экспертами делает сам EI из шага 3: пилот достаётся лучшему *рукаву*, а не лучшему *эксперту*. Thompson поверх экспертов не делали: 20 пилотов — это ~5 на эксперта, веса отражали бы шум. Плохой LLM-рукав просто не пройдёт LCB после пилота.
   - Гипотеза, которую предложил только LLM, попадает в план лишь после пилота. Без этого правила непилотированные догадки модели (≥ 0.125) проходили LCB, и LLM ухудшал результат на всех 10 стресс-мирах: медиана 5.96M против 6.79M.
   - В лог по каждому эксперту пишутся: число рукавов, пилоты на его рукавах, средний obs, hit rate, сколько его рукавов попало в план.
3. **Адаптивные пилоты.** Следующим пилотируем рукав с максимальным *expected improvement* × Σ ARPU ячейки. Размер пилота — 60–200 абонентов: чем спорнее рукав (|μ − лучший сосед| / σ меньше), тем больше (`PILOT_SIZING="adaptive"`); рукав, уже уверенно лучше или хуже соседей (|z| > 2), не перепроверяем. Так 20 пилотов расходятся по крупным ячейкам, а не уходят на один рукав.
   - Апостериор совместный (`JOINT`): θ = β0 + β1·μ_истории + u. Пилот любого рукава уточняет β, а через него — все рукава: если история врёт, β1 уходит к 0, и непилотированные рукава перестают наследовать её μ. Шум пилота `0.804/√n` из документации среды, поэтому пилот на 200 абонентах весит больше пилота на 60.
   - Пилот выбирается по knowledge gradient минус цена (`PILOT_VALUE="voi"`): насколько пилот может поменять решение по ячейке, за вычетом стоимости SMS, вытесненных из плана контактов и с учётом выгоды самого пилота.
   - Масштаб prior не выбирается одной точкой, а усредняется по всей сетке с весами правдоподобия пилотов (`SCALE_MODE="bma"`). Одна точка по 8 пилотам на частых переходах решала, что эффект растёт с долей, и редкие переходы с крупным эффектом не пилотировались никогда. При усреднении вариант «эффект не зависит от доли» сохраняет вес, пока пилоты его не опровергнут.
   - Адаптивный режим (`ADAPT`): после 8 пилотов агент подбирает масштаб prior по правдоподобию. Если оба множителя на минимуме сетки (пилоты укладываются в шум вокруг истории), история надёжна — оставшиеся пилоты идут полного размера на лучшие кандидаты плана и сами приносят деньги. Иначе разведка продолжается как раньше.
   - Перед планом масштаб prior (постоянная часть и часть от доли перехода) подбирается по правдоподобию пилотов на сетке (`SCALE_AT="end"`). Разведка при этом идёт с широким prior: подбор после каждого пилота рано сужал его и ухудшал `keep=0.5`.
   - Разведка останавливается, когда кончились пилоты или EI упал ниже 0.5% от стартового, либо сработал резерв бюджета.
   - Если есть [база знаний](data.md#база-знаний), её наблюдения применяются до разведки тем же апдейтом.
4. **План.**
   - Опция = (ячейка, target, канал) с ожидаемым net > 0. Рукав идёт в план любым каналом, если `μ − 0.5σ > 0`; при `μ > 0`, но LCB ≤ 0 — только бесплатным push (`PUSH_FILL`).
   - MILP (`scipy.optimize.milp`, `PLANNER="milp"`) выбирает не больше одной опции на ячейку и максимизирует Σ net при лимитах охвата, бюджета, ≤10 кампаний `arpu × "tA;tB" → target, channel` и ≤5000 абонентов в кампании. Жадный план терял 1.5–2.5 тыс. контактов, когда групп выходило больше 10, и выбирал target без оглядки на то, с кем ячейку можно объединить.
   - Нет `scipy` или решатель не справился → прежний жадный план: охват по ценности на контакт, канал с push и жадным апгрейдом по Δnet/Δcost.
5. **CatBoost-prior (`PRIOR_MODEL`, по умолчанию выключен).** Вместо группового среднего истории μ рукава считает CatBoost по признакам абонентов аудитории. Режимы, запуск и почему выключен — [catboost.md](catboost.md).
6. **Fallback.** Любая ошибка или пустой план → одна кампания, а не падение и не пустой ответ (ТЗ требует ≥1): sms по лучшему рукаву, если он проходит LCB, иначе бесплатный push на наименее убыточную ячейку. `stress_eval.py` проверяет это в мире «нет `data/`, все эффекты отрицательные».

## Честная игра
- `agent.py` импортирует только stdlib (math, json, os, time, hashlib, urllib, pathlib) и numpy/pandas; `catboost` (в `requirements.txt`) — только в режимах `catboost_*`.
- Из env он использует только публичные атрибуты и `run_pilot`, с диска читает только `data/change_tariff.csv` и `data/traffic.csv`.
- Ключ LLM не хардкодится: берётся из `os.environ["OPENAI_API_KEY"]` (локально можно `OPENROUTER_API_KEY`). В LLM уходят только агрегаты по ячейкам, а не строки абонентов (`PRIVACY_MODE`, см. [privacy gateway](lab.md#privacy-gateway)).
- Лимит 10 минут: `act` ставит дедлайн `TIME_LIMIT = 480` с. LLM-эксперт пропускается, если до дедлайна меньше 60 с (таймаут вызова), разведка останавливается на дедлайне, и план строится по уже проведённым пилотам.
- `stress_eval.py` — локальный стенд: строит среду через публичный `make_environment` со своими искажёнными эффектами и агенту не нужен.
