# Лаборатория версий (`lab.py`)

Цикл самоулучшения поверх агента. Агенту не нужен, состояние хранится в Postgres (см. [хранилище](cockpit.md#хранилище)). Доступна роли `admin` в кокпите и через `/api/lab/*`.

```
матрица тестов → детекторы проблем → патч (LLM через privacy gateway или шаблон)
→ новая draft-версия → та же матрица → gate против родителя → candidate / failed → promote (кнопкой)
```

## Версия
Набор настроек из allowlist `PATCH_TARGETS` поверх `agent.py`: константы (`LCB_K`, `PRIOR_STD`, размер пилотов…), флаги эвристик, режим privacy и `LLM_PROMPT_EXTRA` (полный список — [configuration.md](configuration.md#константы-агента)). У каждой цели есть тип и границы, значение вне границ отклоняется. Код копируется только у AI-версий (см. [AI-агент](#ai-агент)). У версии есть `parent_id`, `commit_hash`, `prompt_hash`, `config_hash`, diff от родителя и статус `draft → candidate | failed → promoted`.

## Матрица тестов
На каждую версию:
- `local_eval` на 1 и 10 seed;
- `stress_eval` на 10 миров;
- жёсткие миры (`stress_eval.harsh_world`): эффекты перемешаны между переходами, `keep` — сколько правды осталось в истории. На `keep=0` (30 миров) стратегия без пилотов получает ~1/16 оракула — так в описании среды выглядит боевая среда. На `keep=0.5` — 10 миров. В обычных стресс-мирах без пилотов получается около половины оракула: история там почти верна;
- валидация кампаний;
- бюджет и охват;
- время прогона;
- прогон с выключенным LLM;
- сбой и мусор LLM (`check_llm` + `check_never_empty`).

Около 10 с на версию: прогоны идут параллельно в процессах.

## Детекторы
Находят проблемы с доказательствами. Например, `HIGH_VARIANCE_BETWEEN_SEEDS` («медиана +6.8M, но 4/10 миров в минусе») или `WEAK_LLM_CONTRIBUTION` («рукава LLM добавлены, но ни один не попал в план»). Полный список — в `detect()`.

## Ремедиация и gate
- Issues превращаются в ограниченный патч: либо LLM через тот же privacy gateway (в контексте только issues, метрики и границы настроек), либо шаблон.
- Получается новая версия, она проходит ту же матрицу.
- **Gate**: все must-have тесты пройдены; медиана жёстких миров `keep=0` не упала; медиана `keep=0.5` и стресс-миров упала не больше чем на 3%; худший мир `keep=0` не стал хуже (раньше — «прогонов в минусе не больше»: на границе нуля это монетка); 0 отброшенных кампаний. Если родитель оценён старой матрицей, он сначала перепрогоняется.
- Ответы LLM кэшируются в БД по хэшу промпта (таблица `llm_cache`). Иначе gate сравнивал бы шум модели: один и тот же конфиг давал 6.57M и 7.06M в двух прогонах.

## Promote
Только кнопкой и только из `candidate`: константы переписываются в `agent.py` построчно, `submission.csv` пересобирается без ключа. Коммит — вручную. У версии со своим кодом сначала записывается её код, потом константы; работающий сервер подхватывает только константы, код — после перезапуска.

Новые эвристики в `agent.py` выключены по умолчанию, при них план совпадает с `submission.csv`: `RANK_BY="lcb"`, `CHANNEL_MU="lcb"` + `UPGRADE_MIN_ROI`, `META_CONTROLLER`, `PILOT_BUDGET_SHARE`. Включает их только версия, прошедшая gate.

## AI-агент
Вкладка «AI-агент»: локальный Claude Code (`claude`) или Codex (`codex`) правит код `agent.py`, а не только константы. Интеграция — порт harness из NexTask (`harness.py`).

- **Запуск.** Задача, версия-родитель, число шагов и бюджет → `POST /api/lab/ai/runs`. Запуск идёт в фоновом потоке сервера и не зависит от страницы. Запуски хранятся в таблице `ai_run` вместе со статусом, событиями, версиями, стоимостью и токенами. UI опрашивает `GET /api/lab/ai/runs/{id}?after=N` и дочитывает лог с последнего события. Одновременно идёт один запуск (409), каждый шаг — до 30 мин. «Остановить» (`POST …/cancel`) убивает CLI со всеми дочерними процессами. Если сервер перезапустился посреди запуска, при старте запуск помечается `failed`, пережившая сервер CLI добивается, песочница удаляется.
- **Автономный цикл** (`steps` > 1). Каждый шаг: правка → матрица → gate.
  - Принятая версия (`candidate`) становится базой следующего шага.
  - Отклонённая возвращается агенту вместе с причинами gate, метриками попытки против базы и её diff: «не повторяй, попробуй другое».
  - Правка, которая не компилируется или теряет константу, тоже возвращается агенту как причина.
  - Цикл заканчивается, когда агент ничего не изменил («улучшать нечего»), когда исчерпан бюджет или когда CLI упал. Бюджет проверяется перед каждым шагом. Claude, кроме того, получает остаток бюджета как `--max-budget-usd` и останавливается посреди шага; незаконченная правка отбрасывается, перерасход — не больше одного хода. Codex цену не сообщает, для него бюджет не действует.
  - Итог запуска — `best`: последняя принятая версия.
- **Стоимость.** Claude сообщает `total_cost_usd` и токены в конце каждого шага, Codex — только токены. Это цена по API; на подписке — ориентир, а не списание, поэтому бюджет необязателен (пусто — без лимита). Всё суммируется в запуске и пишется в `ai` версии. Стоимость прерванного шага неизвестна: CLI сообщает её только в конце.
- **Песочница.** Временный каталог: исполняемый `agent.py` родителя (его код и константы), организаторский пакет (`environment.py`, `scoring_core.py`, `mock_environment.py`, `local_eval.py`, `stress_eval.py`, `agent_template.py`), `docs/agent.md`, `experiments.md`, `lab.md`, симлинки на `data/` и CSV. Плюс `LAB_TASK.md`: задача, метрики, issues и gate родителя, правила. Назад забирается только `agent.py`, каталог удаляется.
- **Результат.** Если `agent.py` изменён, компилируется и все константы `PATCH_TARGETS` на месте, создаётся версия `kind=ai`. У неё свой код (`source`, `source_sha`), константы читаются из него, лог агента сохраняется. Версия сразу уходит в матрицу. Её потомки, в том числе авто-исправления, наследуют код.
- **Оценка кода.** На матрицу версии со своим кодом поднимается отдельный пул процессов. В каждом воркере модуль `agent` собирается из текста версии. Версии без кода идут на общем пуле с `agent.py`.
- **Карточка версии.** Показывает diff исполняемого `agent.py` против родителя (`GET /api/lab/versions/{vid}/code`) и лог агента. Кнопка «AI-агент» запускает следующую итерацию от этой версии.
- **Безопасность.** Только admin. Из окружения CLI убраны `OPENAI_API_KEY`, `OPENROUTER_API_KEY`, `DATABASE_URL`, `AUTH_*`.
  - Claude: `--permission-mode acceptEdits`, `--strict-mcp-config`. Из Bash разрешены только `python3 local_eval.py`, `python3 stress_eval.py` и `tail`/`head`/`grep`/`ls`/`cat`/`wc`/`sort`. `python3:*` не годится: так проходит `python3 -m pip install`. Отказы видны в логе строками `отказ: …`.
  - `python3` агента — интерпретатор сервера (с pandas), а не первый попавшийся в PATH.
  - Codex: `sandbox_mode="workspace-write"`, `approval_policy="never"`, MCP-серверы из `~/.codex/config.toml` выключены.
- **Статус CLI.** `GET /api/lab/harnesses` показывает, установлен ли CLI и выполнен ли вход (`claude auth status`, `~/.codex/auth.json`). Войти: `claude auth login` / `codex login` в терминале.

```bash
python3 harness.py   # self-check парсеров + статус CLI
```

## Privacy gateway
`safe_context` → `llm_proxy` → `_parse_llm` в `agent.py`, общий для LLM-эксперта и ремедиации:
- в LLM уходят только ячейки и медианы полей `LLM_FIELDS`;
- ячейки меньше `K_MIN` идут без статистик;
- поле вне allowlist блокирует запрос;
- каждый вызов пишется в аудит;
- режимы: `aggregate_only`, `synthetic_only` (шум, округлённые n), `debug_safe` (ни одного числа об абонентах).

## Первые замеры
10 стресс-миров, живой `gpt-4o-mini`:

| версия | медиана | gate |
|---|---|---|
| baseline, промпт через gateway | 6.57M | — |
| baseline, прежний промпт ([ablation экспертов](experiments.md#ablation-экспертов)) | 7.14M | — |
| `RANK_BY=lcb` | 6.95M | пройден |
| `CHANNEL_MU=lcb`, `UPGRADE_MIN_ROI=1` (предложил LLM) | 6.24M | отклонён |

Разница между двумя промптами — один ответ LLM на прогон, то есть в пределах шума. Без ключа baseline совпадает с `exp_prior` (6.79M).

```bash
python3 lab.py    # self-check: validate, детекторы, gate, round-trip констант, быстрая матрица
```
