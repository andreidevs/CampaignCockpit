# Данные, эксперименты и отброшенные идеи

Как проверялся агент и почему он устроен именно так. Команды для воспроизведения — [testing.md](testing.md).

## Что показали данные
- **История ≠ аудитория.** Общих ID нет.
  - В аудитории 59% HIGH-абонентов, в истории 35%. Медиана ARPU 5930 против 3700.
  - Самые ценные тарифы в аудитории встречаются в истории заметно реже: tariff_8 — 30% против 14%, tariff_14 — 8% против 2%.
  - HIGH в истории в среднем даёт downsell (медиана Δ% = −0.12), LOW — upsell (+0.79). Prior по HIGH пессимистичен, но именно там основная ценность. Поэтому пилоты выбираются по EI × Σ ARPU, а не по prior.
- **Prior внутренне стабилен.** Split-half корреляция средних по переходам (from, seg, to) — 0.84. Без истории остаются только 3 из 63 ячеек (0.1% ARPU). Слабое место prior — перенос на другую выборку, а не шум, поэтому ширина prior 0.25.

### Поправка prior по трафику (`USE_FIT`)
`traffic.csv` описывает только абонентов из истории, с аудиторией пересечения нет. Трафик снят за апрель–сентябрь, переходы — в октябре, так что утечки будущего нет.
- Агент считает долю абонентов, чей трафик влезает в пакет target, отдельно в истории и в аудитории ячейки. Prior сдвигается на β × разницу этих долей.
- Наивно «влезает → upsell» даёт β = 0.38. Но внутри одного перехода (from, seg, to) β = 0.023, 95% ДИ [−0.02; 0.06]. Разница объясняется тем, *какие* переходы популярны, а не тем, как трафик ложится в пакет.
- Сравнение на 10 нейтральных мирах и 10 мирах, где эффект fit заложен (β = 0.25): с честным β = 0.023 план идентичен варианту без поправки. Наивный β = 0.25 даёт +2% медианы — в пределах шума, в нейтральных мирах минимум хуже.
- Поправка включена: она выводится из данных и ничего не ломает, но на решения сейчас не влияет. `arpu_monthly.csv` не используется: ARPU аудитории уже есть в `predicted_arpu`.

### CatBoost-prior не прошёл gate
По строкам модель точнее группового среднего, но внутри ячейки target выбирает не лучше. Против текущего агента: `keep=0` медиана выше (11.66M против 10.95M), но худший мир хуже (0.77M против 1.25M), стресс −10%. Замеры и разбор причин — [catboost.md](catboost.md#результаты-почему-выключен).

## Стресс-миры
`stress_eval.py` искажает эффекты мока (pct × U(0.5, 2) + N(0, 0.3)), имитируя судейскую среду. Медиана по 10 мирам: агент 6.9M, шаблон 0.6M, prior-only 5.8M, оракул 11.1M.

## Кандидаты и адаптивные пилоты
Две правки, включены вместе; по отдельности каждая почти ничего не даёт. Без LLM, gate-миры как в `lab.py` (медиана / худший мир):

| | `keep=0`, 30 миров | `keep=0.5` | стресс | `--struct` |
|---|---|---|---|---|
| было | 3.91M / −1.37M | 5.77M / 2.32M | 6.79M / 3.72M | 5.80M / 4.09M |
| только адаптивный размер | 7.06M / 0.44M | 5.96M / 1.77M | 7.60M / 3.71M | 5.89M / 3.76M |
| только история первой | 5.13M / −2.24M | 6.09M / 2.32M | 7.04M / 3.67M | 5.81M / 3.85M |
| **обе** | **10.95M / 1.25M** | 6.89M / 1.84M | 6.94M / 3.67M | 6.13M / 4.17M |

- **История первой.** Раньше `_expert_prior` ранжировал target по `prior.get(k, 0)`: пара без истории (μ = 0) обгоняла переход с μ < 0. В HIGH-ячейках (медианный Δ% < 0) top-4 заполняли пустые пары — высокий EI при μ = 0 и σ = 0.25, пилоты уходят на них, а в план они не попадают (LCB < 0).
- **Адаптивный размер** (`PILOT_SIZING="adaptive"`). С фиксированным размером EI тратил 12–20 из 20 пилотов на один рукав крупнейшей ячейки, остальные крупные ячейки шли в план по prior без проверки — в `keep=0` это лотерея. Адаптивный не перепроверяет уверенный рукав, пилоты расходятся по ячейкам.
- **Проверка на свежих seed** (100+, в подборе не участвовали): 10.84M / 0.92M против 6.60M / 0.37M на `keep=0`, `keep=0.5` 6.52M против 3.88M, стресс 6.22M против 6.05M, `--struct` 5.48M против 5.44M. Минус: худший `keep=0.5`-мир хуже на обоих наборах (1.84M против 2.32M, 2.51M против 3.24M) — gate его не проверяет.
- `keep=0`: агент теперь лучше шаблона (10.95M против 7.63M; было 3.91M — хуже) и 41% оракула. На моке (`local_eval --runs 10`, история = правда) тоже лучше: медиана 4.52M против 4.42M, seed 42 — 4.81M против 4.43M.
- **Проверены и не нужны** поверх этих двух правок:
  - VOI вместо EI (`PILOT_VALUE="voi"`): `keep=0` 10.62M, но стресс 6.25–6.76M и хуже на свежих seed;
  - резерв 5 последних пилотов на перепроверку крупнейшей неуверенной ставки плана: на seed подбора +0.6M стресса, на свежих −0.4M на `keep=0` и `keep=0.5`, шум.
- **Не помогли вместо адаптивного размера** (только с историей первой, ни один не прошёл gate): `LCB_K` 0.75 / 1.0; не пускать непилотированный рукав ячейки > 2M ARPU; штраф `k += 10…30 · доля ARPU ячейки`; доверие истории по пилотам (μ непилотированных × наклон obs на prior — ρ шумный: пилоты на 5–8 спорных рукавах). Всё, что спасало худший `keep=0`, резало стресс на 1–2M.

## Строже только для HIGH (`LCB_K_HIGH`)

Общий `LCB_K_PILOT` 0.75 / 1.0 поднимает медиану на моке, но худший seed падает с 3.59M до 3.03M. Поэтому `k = 1.0` только для HIGH, медиана / худший:

Выигрыш — в основном мок, где история = правда. Выключен (`LCB_K_HIGH = 0.5`).

## Пилоты только на μ > 0 (`PILOT_POS_ONLY`)
Risk score (доля уникальных абонентов с отрицательным эффектом) почти целиком дают пилоты: на моке ~1 660 абонентов в пилотах на рукава с отрицательным эффектом, план перекрывает ~100 из них. Финальные кампании в минус почти не уходят. «Лечить» ячейки таких пилотов push-кампанией на лучший μ > 0 хуже: риск 23% → 37%, потому что непроверенный push задевает всю ячейку.

Вариант, при котором EI выбирает только из рукавов с μ > 0 (20 seed: 0–9 и 100–109; медиана / худший, риск — медиана):

| мир | было | `PILOT_POS_ONLY` | Nomad | Yakuza |
|---|---|---|---|---|
| мок | 4.57M / 3.05M, 23% | **4.99M / 4.47M, 0%** | 4.43M / 3.67M, 3.3% | 4.82M / 3.01M, 0% |
| стресс | 6.37M / 3.42M, 22% | **6.92M / 3.94M**, 8% | 6.30M / 3.49M, 5.6% | 6.29M / 3.07M, 11% |
| `keep=0` | **11.88M** / 1.11M, 13% | 9.47M / **1.77M**, 18% | 7.04M / −0.01M, 13% | 7.59M / 0.18M, 21% |
| `keep=0.5` | **6.69M** / 1.86M, 12% | 6.06M / **2.53M**, 6% | 5.27M / 2.18M, 7% | 4.41M / 2.23M, 16% |
| `--struct` | 6.05M / 3.46M, 21% | 6.19M / **4.49M**, 7% | 5.74M / 3.56M, 4% | **6.68M** / 3.43M, 4% |

**Не прошёл gate**: медиана `keep=0` −20% (11.88M → 9.47M), и риск там не падает (13% → 18%): история бесполезна, μ > 0 не значит, что эффект положительный. 0% риска на моке — следствие того, что в моке история = правда; у Nomad и Yakuza так же. Ниже 1% на искажённых мирах не держит ни один агент. Выключен.

## Knowledge gradient + адаптивный режим (после разбора решений других команд)

## `keep0c`: байесовское усреднение масштаба (`SCALE_MODE="bma"`)
Разбор `keep0c` (эффект и конверсия перемешаны) против flora: её пилоты — на редких переходах (медиана доли 0.08–0.23), наши — на частых (0.27–0.41); лучший target крупных ячеек в `keep0c` — переход с долей 0.00–0.08. Одна точка сетки масштабов по 8 пилотам на частых переходах давала (0.5, 0.25) → `ADAPT` считал историю надёжной, план — 1 ячейка (2.4M против 15.3M у flora на seed 5000).
- больше кандидатов (`ARMS_PER_CELL` 6–8) + шире `SD0`: покрытие лучших рукавов 72% → 100%, но 20 пилотов размываются, хуже во всех мирах;
- масштаб по ходу разведки только вверх (`SCALE_EXPLORE="widen"`): правдоподобие по частым переходам вверх не тянет, эффект на одном наборе seed;
- **усреднение по сетке масштабов с весами правдоподобия**: пока данных мало, широкий вариант сохраняет вес.

## `pessimistic`: проверены и не взяты
flora лучше в 80% миров `pessimistic` (Δ% ARPU − 0.15 у всех переходов), разница небольшая (медиана −0.18M); редкие крупные провалы — бесплатный push на крупную HIGH-ячейку с μ > 0 (seed 5027: −1.26M на 4 737 контактах).
- `PUSH_K` (push только при μ − k·σ > 0): 0.25 / 0.5 — в пределах шума, в `pess` без изменений; выключено (`PUSH_K = 0`).
- `B2` — общий сдвиг Δ% ARPU как регрессор β2·доля в совместной модели: 0.1 улучшает худшие миры (stress 3.81 → 4.54M, keep0 6.43 → 7.42M на seed 0–9), но на 270 мирах доля 0.912 → 0.904, `keep0c` 6.50 → 6.05; выключено (`B2 = 0`).

## `keep0c`: все переходы в крупных ячейках (`ARMS_BIG_FRAC`)
Где теряем (270 миров, упущено до лучшего из 44 команд): `keep0c` — 131M из 219M. В худших мирах `keep0c` лучший — то wai (6 из 13), то flora (4), то redorda: выигрывает тот, кто нашёл «джекпот». Джекпоты — в крупнейших HIGH-ячейках (tariff_8 — 25% ARPU, tariff_10 — 16%, tariff_4 — 11%) на редких переходах (доля 0.00–0.07), которых нет в top-4 кандидатов: flora на seed 5002 — tariff_8/HIGH → tariff_21 (доля 0.00), +13.7M.
- `FLAT_PRIOR` (0.3 / 0.5 / 0.7 априорного веса на «плоских» точках сетки масштабов): `keep0c` не растёт — узкое место уже не prior; выключено.
- `ARMS_BIG_FRAC=0.10`: в ячейках с ≥ 10% ARPU — все переходы из истории, в остальных 4. Мок не меняется (`submission.csv` тот же), на 270 мирах 0.912 → **0.916**, `keep0c` 6.50 → 6.69, `keep0` 27.81 → 28.34, history 7.92 → 7.61; против flora +0.013 доли (95% ДИ −0.009…+0.034, P(>0) = 87%). 0.05 / 0.03 — хуже на seed 100–109.
- `SEED_BIG` (1–3 пилота полного размера в каждую крупную ячейку до основной разведки): 1 — +0.1 на быстром стенде, но на 270 мирах 0.916 → 0.908 (`keep0c` 6.69 → 6.49); 2–3 — хуже в сумме. Пилоты, отнятые у KG, стоят столько же, сколько дают; выключено.
- Пилоты всегда полного размера (как у flora) поверх KG + BMA: 200 — сумма искажённых миров 10.04 → 8.91 (seed 0–9), 9.91 → 8.50 (100–109), `keep0c` тоже ниже (10.18 → 6.55, 7.54 → 6.05); 150 — хуже; `PILOT_MIN=120` — шум. Адаптивный размер 60–200 остаётся: при 20 пилотах число проверенных гипотез важнее точности каждой.
- `TAIL_K` — поправка KG на тяжёлый хвост эффектов (sd сдвига от пилота × k): только в крупных ячейках (1.5 / 2) — хуже на обоих наборах seed; во всех ячейках, k = 2 — на 270 мирах `keep0c` 6.69 → 7.15, `keep0` 28.34 → 29.41, но `stress` 8.41 → 7.87, `keep0.5` 14.41 → 14.05, итог 0.916 → 0.906. Пилоты уходят на «лотерейные билеты» там, где история почти верна; выключено (`TAIL_K = 1`).
- `TAIL_UNRELIABLE` — та же поправка только если после 8 пилотов история признана ненадёжной (постоянная часть масштаба ≥ 2×): 1.5 / 2 — сумма искажённых миров 10.04 → 9.90 / 9.81 и 9.91 → 9.92 / 9.63, `keep0c` ниже. Детектор в `keep0c` в половине миров считает историю надёжной, а в `keep0` добавлять уже нечего (доля от лучшего 0.99); выключено.
- Пилоты через push (`PILOT_CH="push"`): мок 5.67 → 5.82 (выше flora), но искажённые миры 10.04 → 9.71 и 9.91 → 9.56, худший `keep0` 12.04 → 5.57: бесплатный пилот в 1.69 раза менее информативен на контакт, и там, где история врёт, это дороже сэкономленного бюджета. Не взято — это подгонка под мок.
- Общие эффекты целевого тарифа / ARPU-сегмента в совместной модели (`TARGET_SD`, `SEG_SD`) — против `struct`: 0.03 даёт struct +0.6M на seed 0–9, но на 270 мирах 0.916 → 0.910 (`keep0c` 6.69 → 7.48, мок 5.65 → 5.49, struct без изменений); 0.06 / 0.1 — хуже; выключено.
- KG с корреляциями (`CORR_KG`): пилот сдвигает все рукава через общие коэффициенты, польза = E[V(μ + Δμ)] − V(μ), V — лучший μ по ячейкам. Сумма искажённых миров 10.04 → 8.99 и 9.91 → 9.59, `keep0c` скачет (10.18 → 4.39, 7.54 → 9.24), худший `keep0` −0.54M: V без лимитов охвата и бюджета переоценивает «диагностические» пилоты; выключено.

## Где остался резерв: разложение потерь
Среднее по 4 мирам на семейство, млн у.е. «Потолок» — LP по целым ячейкам со знанием истинных эффектов, без затрат на пилоты и лимита 10 кампаний; «знания» — разница между MILP-планом на истинных эффектах наших кандидатов (при тех же пилотах, бюджете и охвате) и MILP-планом на наших средних оценках; «осторожность» — между планом на средних без порога и нашим планом с LCB.

| семейство | потолок | структура (10 кампаний, пилоты) | знания | осторожность | покрытие кандидатов | мы |
|---|---|---|---|---|---|---|
| мок | 6.44 | 0.68 | 0.27 | 0.00 | 0.01 | 5.48 |
| stress | 10.07 | 1.69 | 0.82 | 0.00 | 0.01 | 7.56 |
| keep0 | 28.77 | 4.39 | 3.24 | −0.13 | 0.00 | 21.26 |
| keep0.5 | 14.17 | 2.19 | 3.17 | 0.00 | 0.00 | 8.81 |
| struct | 10.73 | 1.34 | 1.76 | 0.00 | 0.00 | 7.63 |
| keep0c | 29.74 | 3.90 | 11.44 | −0.02 | 1.78 | 12.64 |
| pessimistic | 4.93 | 0.68 | 0.22 | 0.00 | 0.32 | 3.71 |

- Порог LCB ничего не стоит: план по средним без порога совпадает с нашим — все опыты с порогами не могли дать эффекта.
- Мок почти выжат: 0.27M до идеального плана при тех же пилотах.
- Резерв — знания там, где история врёт. Точное знание только трёх крупнейших ячеек (все HIGH, 51% ARPU) дало бы `keep0c` 12.64 → 18.40, топ-10 ячеек (84%) — 23.18; в `keep0` / `keep0.5` / `struct` знание размазано: топ-10 даёт +1.5 / +2.4 / +0.9.

### Групповые пилоты — не прошли
`run_pilot` принимает список текущих тарифов через `;`: один пилот измеряет target сразу в нескольких ячейках (наблюдение = Σ w·θ, веса ∝ числу абонентов). Совместная модель обобщена на линейные наблюдения (`y = H·θ + шум`, одиночный пилот — one-hot строка; при одних одиночных пилотах апостериор совпадает с прежним до 1e-17).
- Просеивание до разведки (4 / 6 / 8 групповых пилотов по крупным HIGH-ячейкам): seed 0–9 — 10.04 → 9.99 / 10.31 / 10.00, seed 100–109 — 9.91 → 9.03 / 8.90 / 9.07 (`keep0` 23.0 → 19–21, `keep0.5` 11.3 → 7.9–9.5).
- Групповые пилоты в конкуренции с одиночными по KG − цена: 10.04 → 9.06, 9.91 → 8.20, `keep0c` 10.18 → 4.56 и 7.54 → 2.36.
- Причина: групповое наблюдение неоднозначно — поднимает сразу 2–3 рукава, до плана модель не успевает разделить их одиночными пилотами, и в план попадают лишние ячейки; заранее выданные групповые пилоты отнимают пилоты у ячеек, где знание нужнее. Код удалён; при 20 пилотах информация упирается в их число, а не в способ задавать вопросы.

### Структурная потеря: лимит кампаний почти ничего не стоит, пилоты — много
Среднее по 3 мирам, млн: LP-потолок (без лимита 10 кампаний) → MILP с 10 кампаниями на истине без пилотов → то же с нашими пилотами.

| семейство | потеря от лимита 10 кампаний | потеря на накладных расходах пилотов (охват, бюджет) |
|---|---|---|
| мок | 0.15 | 0.53 |
| stress | 0.07 | 1.67 |
| keep0 | 0.90 | 3.36 |
| keep0.5 | 0.39 | 1.87 |
| struct | 0.05 | 1.07 |
| keep0c | 0.61 | 2.57 |
| pessimistic | 0.09 | 0.59 |

Пилоты занимают ~3.4 тыс. из 15 тыс. контактов, а в идеальном плане охват и бюджет используются полностью. Проверено, окупаются ли:
- размер пилота по KG − цена из сетки (`PILOT_N_GRID`): 20/40/80/160 — на 270 мирах 0.916 → 0.916 (−0.0009, 95% ДИ −0.010…+0.009): `keep0` +1.6M, history +0.6M, но stress −0.3M, struct −0.2M, мок −0.1M; 30/60/100/150/200 — 0.911. Не взято, код удалён;
- лимит доли охвата на пилоты (`PILOT_CONTACT_SHARE` 0.12 / 0.15 / 0.20 против ~0.23 сейчас): хуже на обоих наборах seed (10.04 → 9.26…9.87, 9.91 → 8.86…9.64).

Вывод: пилоты окупают свои накладные расходы — всё, что экономит контакты за счёт знаний, теряет больше, чем экономит.

## Проверены и отброшены
Хуже минимум на стресс-мирах при той же медиане:
- калибровка prior общим сдвигом «пилот − prior»: медиана 6.75M, минимум 3.4M против 3.7M;
- 3 последних пилота на перепроверку крупнейшей неуверенной ставки (против winner's curse): минимум 2.9M;
- эксперт-эвристика «upsell на самый дешёвый тариф не дешевле текущего, чей пакет вмещает медианный трафик ячейки», 2 рукава на ячейку с μ = 0: медиана 6.93M против 6.79M, минимум 3.53M против 3.72M (лучше на 3 мирах, хуже на 4). Лишние рукава размывают пилоты, поэтому эксперт удалён.
- частичный пулинг пилотов по target или сегменту (эмпирический Байес: сдвиг непилотированным рукавам с весом τ²/(τ²+σ²/n), τ² по методу моментов). Проверяли и на `--struct` — мирах, где история ошибается системно: общий сдвиг на target (sd 0.2) и сегмент. Итог 0 изменений на 28 из 30 миров: при 20 пилотах и ошибке prior 0.25 на рукав оценка τ² почти всегда 0, структуру такого масштаба не видно. Агент на `--struct`: медиана 5.8M, оракул 10.1M;
- EI как ценность информации (`EI − max(μ − best, 0)`), чтобы не пилотировать уверенного лидера повторно: медиана хуже на 3 из 4 типов миров (`world` 6.08M против 6.79M), лучше только на `keep=0`. Повторные пилоты лидера крупнейшей ячейки окупаются сами: пилотные контакты тоже идут в зачёт.

## Ablation экспертов
Реальный LLM (`gpt-4o-mini`, один ответ на все seed), 10 стресс-миров:

| | медиана | минимум |
|---|---|---|
| prior + llm (`agent`) | 7.14M | 3.18M |
| только prior (`exp_prior`) | 6.79M | 3.72M |

LLM лучше на 3 мирах, хуже на 5, на 2 без разницы; суммарно около +1%, то есть на уровне шума. На моке (`local_eval`, 3 seed) LLM хуже на 3–6%: там история в точности совпадает с эффектами, и любой пилот, ушедший с prior-гипотез, стоит денег. LLM оставлен, потому что в боевой среде эффекты другие и история там менее надёжна. Без ключа `agent` совпадает с `exp_prior`. `check_llm` подменяет вызов API и проверяет две вещи: мусорные предложения LLM отсеиваются, падение API не ломает план.

## Коэффициент LCB
`0.5σ` выбран на таких мирах и на пессимистичных (эффекты хуже истории): при `0σ` агент там уходит в минус, при `1σ` слишком осторожен.
